Part 2（Cheng）反复强调的点

公式只认一套
  • AMAT = HR × HT + MR × MT，其中 MT = HT + MP（先查缓存（cache），没命中（hit）再去主存（main memory））。讲义上写成 "HT + HP" 是笔误。
  • 另一种写法 AMAT = HT + MR × MP 结果一样。老师说选一个公式用到底，别混着用。
  • 实际 CPI = 理想 CPI + 存储停顿（memory stall）；停顿（stall） = 每条指令访存（memory access）次数 × 缺失率（miss rate） × 缺失代价（miss penalty），指令和数据分开算再相加。
  • 每条指令访存次数 = 1（取指（instruction fetch））+ load/store 占比。题目说"1.2 次取指"就用 1.2（见练习 T7.6+）。
  • 缺失代价给的是 ns 时，先用时钟频率（clock rate）换成周期数（T8.3：50 ns ÷ 2 ns = 25 周期，CPI = 2 + 0.75 + 0.5 = 3.25）。
地址位与硬件
  • 地址位 = log₂(主存（main memory）字节数)；Offset = log₂(块字节数)；Index = log₂(组数（number of sets）)；Tag = 其余。
  • 组数 = 行数 ÷ 路数（number of ways）。直接映射（direct mapped）：组数 = 行数；全相联（fully associative）：只有 1 组，Index = 0 位。
  • 注意 K/M/G：1 KB = 2¹⁰ = 1024 字节，不是 1000；"256 KB" 和 "256 B" 差了 10 位。块大小（block size）给的是"字"时先乘 4 换成字节。
  • 老师喜欢的算法：块号（block number） B = ⌊地址 / 块大小⌋，Index = B mod 组数，Tag = ⌊B / 组数⌋；或者直接把地址写成二进制切开。
  • 比较器（comparator）：个数 = 每次要查的行数（直接映射 1 个，全相联 = 行数，k 路 = k 个），每个比较器的位数 = Tag 位数，XOR 门数 = 两者相乘。T8.2 两路是 2 × 15 = 30（老师口误说成 32）。
  • 还会考"反推"：给 Tag 位数和块数，倒推块大小和容量；Index 算出来是 0 就说明是全相联。
手算缓存（cache）轨迹
  • 每一步：先算块（地址 ÷ 块大小（block size）取整 → 这一块的起止地址），再看 Index 选组，组内比 Tag。
  • 命中（hit）：什么都不换，只把这一行的 TSLR 清零、其他行加一。缺失（miss）：有空行先填空行，没空行踢 TSLR 最大（最久没用）的。
  • 第一次访问某个块 = compulsory，即使同时把别人踢出去也算 compulsory（老师答疑时确认，compulsory 优先）。
  • 全相联（fully associative）里的重复缺失 = capacity（全相联没有冲突缺失）；直接映射（direct mapped）/组相联（set associative）里的重复缺失 = conflict。
  • Ex 8.1 的答案：8 次缺失、4 次命中、命中率（hit rate） 33.3%（讲义上的 3.3% 是笔误）。
概念题素材
  • 写策略专题 → 写直达（write-through）：写缓存（cache）同时写主存（main memory），简单、无脏位（dirty bit），但访存（memory access）流量大。写回（write-back）：只写缓存并置脏位，被踢出时才写回主存，性能高，现代缓存多用写回。
  • 写分配（write allocate，先把块搬进缓存再写，常配写回）vs 不写分配（no-write allocate）（直接写主存）。写缓冲（write buffer）让 CPU 不用等写完。
  • 块太大：缺失率（miss rate）先降后升（块数变少，冲突/容量缺失（capacity miss）增加），缺失代价（miss penalty）变大；常用 64–128 字节。
  • 加大容量比加相联度效果更明显；相联度高了以后再加收益很小。
  • CPU 变快、内存不变：缺失代价按周期算会变大（时钟翻倍，100 → 200 周期，CPI 5.44 → 8.88），停顿（stall）占比越来越高。
  • 直接映射（direct mapped）：硬件简单但不灵活；全相联（fully associative）：冲突最少但比较器（comparator）多；组相联（set associative）是折中。

Q1存储层次：谁最快 · Memory hierarchy概念
EN

Which memory component is normally the fastest?

中

下面哪种存储部件通常最快？

  1. AMain memory
  2. BL2 cache
  3. CProcessor register
  4. DSolid-state drive
考的知识点

存储层次从上到下：寄存器（register） → L1 缓存（cache） → L2 / L3 缓存 → 主存（DRAM）→ 辅存（SSD / 硬盘）。越往上越快、小、每字节越贵，越往下越慢、大、便宜。

  • 寄存器在 CPU 核内部，运算直接读写它，是整个层次里最快的。
  • 缓存（SRAM）在 CPU 芯片上：L1 比 L2 快、也比 L2 小；L2 又比主存快得多。
  • 主存是 DRAM，在 CPU 芯片外面；SSD 是辅存，比主存慢几个数量级。

同类题会反过来问"哪个最慢 / 最大 / 每字节最便宜"（答案都是最底层的辅存），或者给几种部件让你按速度排序。

手册对应：7.2 存储层次与局部性（locality）

答案与解析 · Answer

答案：C　Processor register

寄存器（register）在 CPU 内部，处在存储层次（memory hierarchy）最顶层，最快。从快到慢：寄存器 > L2 缓存 > 主存（main memory） > SSD。

陷阱　L2 cache 是缓存，但不是最快的，寄存器和 L1 都比它快。看到 "cache" 别直接选。

考的知识点

局部性（locality）只有两种，判断的关键是"同一个地址"还是"相邻地址"：

答案：B　temporal locality

"反复访问同一个变量" = 同一地址被重复访问 = 时间局部性（temporal locality）。

陷阱　如果题目换成"按顺序访问数组的每个元素"，就是空间局部性（spatial locality）。direct mapping 和 set associativity 是缓存（cache）的映射（mapping）方式，不是程序行为，可以直接排除。

Q6AMAT · Average memory access time计算
EN

A cache has a hit time of 2 ns, a miss rate of 5%, and a miss penalty of 70 ns. What is its AMAT?

中

  1. A3.5 ns
  2. B5.5 ns
  3. C7.0 ns

考的知识点

AMAT（平均访存时间（average memory access time, AMAT））就是每次访问平均花多少时间。两种写法，结果完全一样：

AMAT = HT + MR × MPAMAT = HR × HT + MR × MT，其中 MT = HT + MP （老师的写法）

为什么相等：HR × HT + MR × (HT + MP) = (HR + MR) × HT + MR × MP = HT + MR × MP。

关键在于缺失（miss）的时候也要先花 HT 查缓存，发现没命中（hit）再花 MP 去主存（main memory），所以一次缺失 = HT + MP。老师说选一个公式用到底，别混用。

手册对应：8.1 性能指标与 AMAT 公式

答案与解析 · Answer

答案：B　5.5 ns

AMAT = HT + MR × MP = 2 + 0.05 × 70 = 2 + 3.5 = 5.5 ns验算：0.95 × 2 + 0.05 × (2 + 70) = 1.9 + 3.6 = 5.5 ns
陷阱　A 3.5 只算了 MR × MP，漏了 HT；D 72 是一次缺失（miss）的时间 MT，不是平均值。还有一个不在选项里的错法：0.95 × 2 + 0.05 × 70 = 5.4（缺失时间（miss time）只算 MP、没加 HT）。

Q8地址位划分 · Address fields计算
EN

A 32-bit byte-addressable computer has a 4-way set-associative cache of 256 KB with 64-byte blocks. Which address-field allocation is correct?

中

32 位按字节编址（byte-addressable）的计算机，256 KB 的 4 路组相联缓存（cache），块大小（block size） 64 字节。哪种地址划分是对的？

  1. AOffset 6, index 10, tag 16 bits
  2. BOffset 6, index 11, tag 15 bits
  3. COffset 8, index 10, tag 14 bits
  4. DNone of the above
考的知识点

地址从高到低切成三段：Tag | Index | Offset。固定四步：

  1. Offset = log₂(块字节数)
  2. 行数（块数）= 容量 ÷ 块大小
  3. 组数（number of sets） = 行数 ÷ 路数（number of ways）；Index = log₂(组数)
  4. Tag = 地址位数 − Index − Offset

直接映射（direct mapped）：组数 = 行数；全相联（fully associative）：只有 1 组，Index = 0。1 KB = 2¹⁰ 字节，所以 256 KB = 2¹⁸ 字节。

快捷验算：Index + Offset = log₂(容量 ÷ 路数)，也就是"一路"的大小。本题 256 KB ÷ 4 = 64 KB = 2¹⁶，所以 Tag = 32 − 16 = 16。

手册对应：9.3 地址位划分通用方法

答案与解析 · Answer

答案：A　Offset 6, index 10, tag 16 bits

先像 Q8 那样算出 Offset 和 Index 的位数，再用下面任一种方法求组号（set index），结果一样：

  • 除法 + 取余：块号（block number） = ⌊地址 ÷ 块大小⌋；组号 = 块号 mod 组数（number of sets）；Tag = ⌊块号 ÷ 组数⌋。

  • 例：int 数组（每个 4 字节），16 字节的块装 4 个元素。顺序遍历时 a[0] 缺失、把 a[0]–a[3] 一起搬进来，a[1]–a[3] 都命中（hit），缺失率（miss rate） 1/4 = 25%；换成 64 字节的块，缺失率降到 1/16。
  • 块不能无限大：容量固定时块越大、块数越少，冲突 / 容量缺失（capacity miss）变多，缺失代价（miss penalty）也变大，所以缺失率先降后升（9.2）。
  • 用不上空间局部性的访问：跳着访问（a[0], a[4], a[8]…）、二维数组按列遍历、链表。
  • 考试判断："连续 / 相邻"→ 空间；"同一个变量 / 同一地址反复"→ 时间；一串访问可以两种都有。direct mapping、set associativity、write-back、LRU 是缓存的设计，不是程序的局部性（locality）。

A4替换：组满了踢谁

  • 只有"缺失（miss） + 这一组没有空行"时才需要替换。直接映射（direct mapped）没有选择，不需要替换策略（replacement policy）。
  • LRU：踢最久没被访问的块。课上用 TSLR 计数：命中（hit）或装入的行清零，其他行加一，踢 TSLR 最大的。
  • FIFO：踢最早装进来的块，不管它最近有没有被用过。
  • 例：2 路的一组，访问 A, B, A, C, B：A、B 缺失装满 → A 命中 → C 缺失，踢最久没用的 B → B 缺失，踢 A。命中 1 次。
  • 写回（write-back）策略下，被踢的那一行如果是脏的，要先写回主存（main memory），见 B4。

B1为什么写操作要单独处理

  • 读只是把主存（main memory）的块复制一份到缓存（cache），两边内容一样。写（store）会修改缓存，于是缓存和主存可能暂时存着同一数据的两个不同版本。
  • 写策略（write policy）要解决的问题：怎么保证主存最终拿到正确的值。主存的值在这几种时候要紧：块被踢出缓存时（新值没写回（write-back）就丢了）、I/O 设备（DMA）绕过缓存直接读主存时、多核时别的核来读时。
  • 写和读的另一个区别：写不需要把数据拿回 CPU，所以不一定要让 CPU 等，可以交给写缓冲（B6）。
  • 讲义列了四种机制：写直达（write-through）、写回、写缓冲、缓存一致性（MESI，超出课程范围）。

B2四种情况总表（最重要）

每次访存（memory access）只会是这四种情况之一。两套常见组合：写回（write-back） + 写分配（write allocate）（现代缓存（cache）主流）、写直达（write-through） + 不写分配（no-write allocate）（简单，常配写缓冲（write buffer））。

B3脏位（dirty bit）的一生

脏位（dirty bit）是缓存（cache）每一行额外的 1 位，记录"这一行被写过没有"，也就是主存（main memory）那份是不是已经过期。每一行存：| 有效位（valid bit） V | 脏位 D | Tag | 数据（整块） |

事件脏位主存动作
块从主存搬进缓存（读缺失（read miss）或写分配（write allocate））D = 0读一块
读这一行（读命中（read hit））不变无
写这一行（写命中（write hit），或写分配后的那次写）D = 1无（写回（write-back）策略不写主存）
这一行被踢出，且 D = 1—整块写回主存，再丢掉
这一行被踢出，且 D = 0—直接丢掉，主存那份本来就一样
  • 每行 1 位，不是每个字节 1 位：只改了一个字节，整行也算脏，写回时整块一起写。
  • 只有写回策略需要脏位；写直达（write-through）每次都同步写主存，行永远是"干净"的。
  • 只读过的块 D 一直是 0，踢出时不用写主存，这是写回省流量的原因之一。
  • Tutorial 9.4(c)：三次写之后脏位依次是 1、1、1，直到块被写回、踢出（9.4 脏位）。

B4读缺失也会写主存？会（写回策略下）

这是最容易想不到的一点。写回（write-back）策略下，写操作本身不写主存（main memory），写主存发生在"踢出脏块（dirty block）"的时候，而踢块是由缺失（miss）引起的，读缺失（read miss）也一样。讲义原话：modified blocks are written back only upon eviction (e.g., cache replacement due to a read/write miss)。

  1. 读缺失，要放新块的那一行里是一个脏块；
  2. 先把这个脏块写回主存；
  3. 再从主存读新块进来，D = 0。

所以这次读缺失要做两次主存传输，比普通缺失慢，大约是两倍的缺失代价（miss penalty）。写直达（write-through）没有这个问题：主存永远最新，被替换的块直接丢，讲义说 "read/write misses do not trigger write-backs"，这正是写直达的一个优点（"no need to wait for a block to be written back before replacement"）。

B6写缓冲：让写直达不那么慢

  • 写直达（write-through）每次都要写慢速的主存（main memory）。写缓冲（write buffer）是一个小队列：CPU 把"地址 + 数据"放进去就继续执行，缓冲在后台把它们写进主存。
  • 硬件保证缓冲里的写最终都会写进主存。
  • 缓冲满了（连续写得太快，主存来不及消化），CPU 还是要停下来等。
  • 通常和写直达搭配（讲义："typically uses a write buffer to reduce CPU stalls, unless the buffer becomes full"）。

7.1 冯·诺依曼结构与它的瓶颈

冯·诺依曼结构（von Neumann architecture）的核心是存储程序（stored-program）：指令和数据放在同一个主存（main memory）里。它由这几部分组成：

  • CPU：控制单元（CU）负责取指（instruction fetch）和控制指令执行；ALU 负责算术和逻辑运算。
  • 主存：同时存程序和数据，按字节编址（byte-addressable）（每个地址存 1 个字节）。
  • 系统总线：在 CPU、内存、I/O 之间传数据、地址和控制信号。
  • I/O 设备和辅存（secondary storage）（硬盘、SSD，非易失）。

问题出在"共享"上：指令和数据走同一个存储器、同一条通路。CPU 处理数据的速度远快于数据在总线上搬运的速度，于是 CPU 经常停下来等，这就是冯·诺依曼瓶颈（von Neumann bottleneck）。

技术趋势：容量涨得快，DRAM 延迟（latency）几乎不动
容量增长速度（延迟）增长
逻辑电路每 1.5 年 ×4每 3 年 ×4
DRAM每 3 年 ×4每 10 年 ×2
磁盘每 3 年 ×4每 10 年 ×2

讲义里的 DRAM 数据：1980 年 64 Kb、250 ns，到 1995 年 64 Mb、120 ns。容量涨了 1000 倍，周期时间只缩短一半。CPU 与 DRAM 之间越拉越大的差距被称为存储墙（memory wall）。

怎么缓解瓶颈（讲义列了五条）

  • 缓存（cache）与存储层次（memory hierarchy）：把常用数据放在离 CPU 近的地方。这是本课和接下来两课的主线。
  • 哈佛或混合结构：指令和数据走分开的通路，带宽翻倍。
  • 并行与专用化：多核、GPU、向量机、AI 加速器。
  • 存内/近存计算（PIM）：把处理器和 RAM 做在同一芯片上，减少数据搬运。
  • 更快的互连与存储：例如 3D 堆叠的高带宽内存 HBM。

7.2 存储层次与局部性原理

硬件上有个绕不开的事实：大的存储器慢，快的存储器小。存储层次（memory hierarchy）的思路是把几种存储器叠起来，让程序"看起来"拥有一块又大、又快、又便宜的内存。

寄存器（register）最快 · 最小 · 最贵
L1 缓存（SRAM）~0.5–2 ns · 32 KB 级
L2/L3 缓存（SRAM）MB 级
主存（DRAM）~10–20 ns · GB 级
辅存（SSD / 硬盘）SSD ~50–150 μs · TB 级 · 最便宜
  • 任何时刻，数据只在相邻两层之间复制。靠近 CPU 的叫上层（小、快、贵），远的叫下层（大、慢、便宜）。
  • 层与层之间搬运的基本单位叫块（block）；块放进缓存后占据的位置叫缓存行（cache line）。本课程里 block 和 line 混用。

层次结构之所以有效，靠的是局部性（locality）原理：程序在任一时刻只访问地址空间里很小的一部分（"90/10 规则"：10% 的代码占 90% 的执行时间）。局部性分两种：

类型含义例子缓存怎么利用它
时间局部性（temporal locality）刚访问过的数据很快会再被访问循环变量、查找表、循环体里的指令访问过的数据留在缓存里；满了就淘汰最久没用的
空间局部性（spatial locality）访问某地址后，邻近地址很快会被访问顺序遍历数组：100, 101, 102, 103缺失（miss）时一次取回一整块连续地址
一眼识别两种局部性（locality）

序列 100, 101, 102, 103, 100, 101, 102, 200, 200 同时有两种局部性：100→103 依次递增是空间局部性（spatial locality）；100 又出现、200 连续两次是时间局部性（temporal locality）。Tutorial 9.1(d) 就是这样考的。

打个比方

寄存器（register） = 手里正拿着的那张纸；缓存（cache） = 书桌，只放得下几本书但伸手就拿到；主存（main memory） = 房间里的书架，书多得多但要起身去拿；SSD = 楼下的图书馆，什么都有，跑一趟最慢。命中（hit）就是书在桌上；缺失（miss）就是要去书架拿，多花的时间是缺失代价（miss penalty）。缓存里是副本，在副本上改了值，原件就旧了，这就是 9.4 节写策略（write policy）要解决的问题。

注意：日常说的"手机内存 256 GB"其实是存储空间，相当于这里的辅存（secondary storage）；课程里的主存（内存）专指 RAM。考试题默认只有"一级缓存 + 主存"两层，不用管 L2、L3。

补充：显存（GPU 内存）在哪一层

显存在层次图上和主存是同一层：它本身就是 DRAM，只是不属于 CPU 这座金字塔，而是 GPU 自己那座金字塔里"主存"的位置。

  • 技术上它就是 DRAM。它和主存一样处在"片外、大、比 SRAM 慢"那一层，区别是为带宽设计：数据位宽更宽、频率更高。例如一块 8 GB GDDR7 的笔记本显卡，带宽有几百 GB/s；CPU 的双通道 DDR5 约 80–100 GB/s。单次访问的延迟（latency）并不比主存短，GPU 靠几千个线程同时访存（memory access）把延迟藏起来。
  • 两座金字塔之间隔着 PCIe。CPU 不能像用自己的主存那样透明地用显存，数据要显式拷过去（例如 cudaMemcpy）。PCIe 只有几十 GB/s，远低于显存带宽。这条通路就是 7.1 节冯·诺依曼瓶颈（von Neumann bottleneck）在 CPU 和 GPU 之间的翻版，所以跑深度学习时要尽量让数据一直留在显存里。
  • 集成显卡没有独立显存。核显（以及苹果 M 系列的统一内存）的"显存"就是从主存里划出来的一块，和 CPU 共用同一层 DRAM。
  • 和讲义的联系。7.1 节"怎么缓解瓶颈"里的"GPU 等并行加速器"和"3D 堆叠的 HBM"指的就是这一套：HBM 是贴在 GPU 旁边堆叠起来的显存。

7.3 命中、缺失与 AMAT（课程约定）

老师上课提醒
  • AMAT = HR × HT + MR × MT，其中 MT = HT + MP（先查缓存（cache），没命中（hit）再去主存（main memory））。讲义上写成 "HT + HP" 是笔误。
  • 另一种写法 AMAT = HT + MR × MP 结果一样。老师说选一个公式用到底，别混着用。

本课程默认只有两级：缓存和主存。访问缓存找到了叫命中（hit），没找到就要去主存取块，叫缺失（miss），CPU 为此多等的周期叫存储停顿（memory stall）。几个时间量要分清：

命中时间 Hit time = 缓存访问时间 C 缺失代价 Miss penalty = 主存访问时间 M （本课程默认假设） 缺失时间 Miss time = C + M （先查缓存没找到，再去主存） AMAT = 命中率（hit rate） × 命中时间 + 缺失率（miss rate） × 缺失时间

讲义例子：缓存 1 周期，主存 50 周期，命中率 80%。命中时间 1，缺失代价 50，缺失时间 51，缺失率 0.2，所以 AMAT = 0.8×1 + 0.2×51 = 11 周期。

易错：缺失代价 ≠ 缺失时间

缺失代价（penalty）只是"多出来"的那部分时间；缺失时间（miss time）= 查缓存（cache）的时间 + 缺失代价。题目说"缓存比主存（main memory）快 10 倍"时，按课程约定一次缺失（miss）要花 C + M = 1 + 10 = 11 个单位，而不是 10。Tutorial 7.1 用这个约定算出加速比（speedup）正好是 5：不用缓存每次 10，用缓存 AMAT = 0.9×1 + 0.1×11 = 2。

加速比（speedup）是什么

加速比衡量一项改进让同一件事快了多少倍：

加速比 = T旧 / T新 = 性能新 / 性能旧
  • 大于 1 表示变快了：加速比 4 就是快了 4 倍，时间变成原来的 1/4；小于 1 表示反而变慢了。
  • 前后必须是同一个任务（同一个程序、同一批数据），否则比较没有意义。
Part 2 里的几种写法，本质都是"旧时间 / 新时间"
场景公式课程里的例子
加缓存无缓存每次访问时间 / AMATT7.1：10 → AMAT 2，加速比 5
流水线（pipeline）（指令很多）单周期时间 / 流水线时钟周期（clock cycle）10.4 节：950 ps / 250 ps = 3.8
流水线（n 个任务）顺序总时间 / 流水总时间10.3 节洗衣房：360 / 210 ≈ 1.71
时钟相同，只比 CPICPI旧 / CPI新12.1 节：5 / 1.25 = 4
时钟也变了（最通用）(CPI旧 × T旧) / (CPI新 × T新)T11.8：(4.6 × 0.8) / (1.2 × 1.0) ≈ 3.07

最后一行是通式：每条指令的平均时间 = CPI × 时钟周期，CPU 时间之比就是这两项乘积之比，前面几行都是它的特殊情况。

加速比（speedup）的常见坑
  • 分子分母别放反：慢的放上面、快的放下面，结果才大于 1。
  • "快 3 倍"和"快 300%"不是一回事：加速比 3 是时间变成 1/3；"快了 35%"对应加速比 1.35。T7.3 问"慢多少"，2.7 / 2.0 = 1.35 倍，即多花 35% 的时间。
  • 流水线（pipeline）加速比有上限：各级完全平衡、指令无限多、没有停顿（stall）时，最大加速比 = 级数；不均衡、填充排空、冒险（hazard）停顿都会让它更小。
  • 只看 AMAT 会出错：T9.2 里 2 路组相联（set associative）的 AMAT 更小，但时钟周期（clock cycle）变长，算 CPU 时间之比反而是直接映射（direct mapped）更快。比较要比"整个程序的总时间"。
  • Part 1 的 Amdahl 定律也是加速比：只有比例 f 的部分被加速 s 倍时，整体加速比 = 1 / ((1 − f) + f / s)。T7.1 若按"缺失（miss）只花主存（main memory）时间"的口径算，就是这个公式，得 5.26；按课程口径是 5。

7.4 存储停顿与实际 CPI

老师上课提醒
  • 实际 CPI = 理想 CPI + 存储停顿（memory stall）；停顿（stall） = 每条指令访存（memory access）次数 × 缺失率（miss rate） × 缺失代价（miss penalty），指令和数据分开算再相加。
  • 每条指令访存次数 = 1（取指（instruction fetch））+ load/store 占比。题目说"1.2 次取指"就用 1.2（练习 T7.6+）。
  • 缺失代价给的是 ns 时，先用时钟周期（clock cycle）换成周期数（T8.3：50 ns ÷ 2 ns = 25 周期，CPI = 2 + 0.75 + 0.5 = 3.25）。

理想 CPI 是"所有取指和取数都命中（hit）缓存（cache）、没有流水线（pipeline）冒险（hazard）、没有分支代价（branch penalty）、不等 I/O"时每条指令平均需要的周期数，代表处理器理论上最好的表现。现实中缺失（miss）会带来停顿：

CPU 时间 = (理想周期数 + 存储停顿周期数) × 时钟周期 实际 CPI = 理想 CPI + 每条指令的存储停顿周期 每条指令的存储停顿 = 每条指令的平均缺失代价

先分清：取指 vs 取数

取指（instruction fetch）：把指令本身从存储器读出来。CPU 按 PC 里的地址读出那 32 位指令编码，放进指令寄存器（register） IR，然后 PC 加 4。取数（data access）：指令执行时，去存储器里读或写它要处理的数据。

取指取数
读的是什么指令本身（操作码、寄存器号、立即数（immediate））程序的数据（数组元素、变量）
地址从哪来PC指令算出来的有效地址，如 R2 + 8
哪些指令有每一条都有，课程默认恰好 1 次只有 load / store（DLX 是 load-store 架构）
读还是写只读load 读，store 写
流水线哪一级IF（第 1 级）MEM（第 4 级）
走哪个缓存指令缓存 I-cache数据缓存 D-cache

例：LW R1, 8(R2) 存在地址 1000，R2 = 500。取指：读 Mem[1000]，得到这条指令的编码；取数：读 Mem[500 + 8] = Mem[508]，把值放进 R1。这一条指令访问了两次存储器。ADD R1, R2, R3 只有取指（操作数都在寄存器里）；SW R3, 8(R2) 是取指加一次写数据。

  • 访存次数 = 1（取指）+ load/store 比例（取数）。
  • 缺失率要分别乘：指令停顿 = 1 × I-缺失率 × 代价；数据停顿 = load/store 比例 × D-缺失率 × 代价。
  • 结构冒险（structural hazard）：指令和数据共用一个单端口存储器时，一条指令在 IF 取指、另一条在 MEM 取数，同一周期抢同一个存储器（Lesson 12）。分开的指令/数据缓存（哈佛结构的思路）可以解决。

"load/store 占 40%"是什么意思

这叫指令构成（instruction mix）：程序运行时执行的所有指令里，有 40% 是 load 或 store（两者合起来算，比如 25% load + 15% store），其余 60% 是算术逻辑、分支（branch）这类不访问数据存储器的指令。

设程序执行 1000 条指令：400 条 LW/SW，600 条 ADD、SUB、BEQZ…… 取指：每条都取一次 → 1000 次；取数：只有 400 条 load/store → 400 次 合计 1400 次 → 平均每条指令 1 + 0.4 = 1.4 次访存 数据停顿 = 0.4 × D-缺失率 × 缺失代价　（例：0.4 × 0.05 × 30 = 0.6 周期/条）
要注意
  • 数的是执行次数，不是代码行数：循环里的一条 LW 跑 100 遍就算 100 条，题目给的比例都是运行时的统计。
  • 40% 只用在数据访问上：取指（instruction fetch）那一项每条指令都有，前面乘 1，不要再乘 40%。
  • 给比例时先换成百分比：Exercise 7.1 给的是 4 : 3 : 1，load/store 占 3 / 8 = 37.5%。

情形 1：取指和取数的缺失率、缺失代价相同

每条指令的访存（memory access）次数 = 取指次数 I + 取数次数 D = 1 + load/store 比例 每条指令停顿（stall） = 每条指令访存次数 × 缺失率（miss rate） × 缺失代价（miss penalty）

课程默认每条指令都要取指一次（I = 1），只有 load/store 才访问数据存储器。讲义例子：理想 CPI 2.0，load/store 占 40%，缺失率都是 2%，代价 25 周期 → 访存次数 1.4，停顿 1.4×0.02×25 = 0.7，实际 CPI 2.7，比全命中（hit）慢 2.7/2.0 = 1.35 倍。如果根本没有缓存（cache），每次访存都要 25 周期：停顿 1.4×25 = 35，CPI = 37。

情形 2：指令缓存和数据缓存的参数不同

每条指令停顿 = 1 × I-缺失率 × I-缺失代价 　　　　　　 + load/store 比例 × D-缺失率 × D-缺失代价

讲义例子：理想 CPI 1.1，指令构成 50% 算术、30% load/store、20% 控制。数据缺失率 10%，代价 50。只算数据缺失（miss）：0.3×0.1×50 = 1.5，CPI = 2.6，有 1.5/2.6 = 58% 的时间在等内存。再加上 1% 的指令缺失（0.01×50 = 0.5），CPI = 3.1，停顿占 2.0/3.1 = 64.5%。

解题模板
  1. 写出每条指令的取指（instruction fetch）次数（1）和取数次数（load/store 比例）。
  2. 分别算指令停顿（stall）和数据停顿，相加得每条指令停顿。
  3. 实际 CPI = 理想 CPI + 停顿；停顿占比 = 停顿 / 实际 CPI；变慢倍数 = 实际 CPI / 理想 CPI。
  4. 如果代价以纳秒给出，先换成周期：代价(周期) = 主存（main memory）时间 ÷ 时钟周期（clock cycle）（500 MHz → 2 ns）。

  • 每次引用 a[i] 算一次访存；sum、i 都在寄存器（register）里，不产生访存。

这类题最容易错在"一共访问了几次 a[i]"。老师课上做 Exercise 7.2 时数的是 5 次（i = 0…4，每轮访问一个元素）：无缓存（cache） 5 × 10 = 50 ms，有缓存 (1 + 10) + 4 × 1 = 15 ms，提升 3.3 倍。也就是说 if (a[i] > 0) 和后面的 sum ±= a[i] 读的是同一个元素，只算一次。Tutorial 7.4 的 while (sum < 15 && i < 8) 条件只用寄存器（register），要先模拟到 sum 不再小于 15 时停下，数清实际执行了几轮（4 轮）。

冯·诺依曼瓶颈的根本原因是什么？为什么哈佛结构能缓解它？
根本原因是指令和数据共享同一个存储器和同一条通路，而 CPU 处理数据的速度远快于通路搬运数据的速度，CPU 只能等。哈佛结构给指令和数据各配一条通路，取指（instruction fetch）和取数可以同时进行，带宽翻倍，所以能缓解（但不能消除）瓶颈。
"缺失代价"和"缺失时间"差在哪里？缓存 2 周期、主存 80 周期时分别是多少？
缺失代价（miss penalty）是缺失（miss）时额外付出的时间，课程默认等于主存（main memory）访问时间，即 80。缺失时间（miss time）是缺失时总共花的时间 = 命中时间（hit time） + 缺失代价 = 82。
为什么题目说"每条指令的访存次数 = 1 + load/store 比例"？
每条指令都必须先从存储器里取出来（取指（instruction fetch） 1 次，课程默认每条指令恰好 1 次），而只有 load/store 指令才会额外访问数据存储器。所以访存（memory access）次数 = 1 + load/store 所占比例，例如 40% 的 load/store 对应 1.4 次。
理想 CPI 2.0、停顿 0.7 时，机器比"全部命中"慢多少？停顿占执行时间的多少？
实际 CPI 2.7，慢 2.7/2.0 = 1.35 倍（多花 35% 时间）。停顿（stall）占 0.7/2.7 = 25.9%。注意两个比值的分母不同：一个除以理想 CPI，一个除以实际 CPI。
为什么缓存一次搬"一整块"而不是只搬 CPU 要的那个字节？
为了利用空间局部性（spatial locality）：CPU 访问一个地址后，很可能马上访问相邻地址。一次搬整块，后面相邻的访问就都能命中（hit）。代价是块越大，单次缺失（miss）要搬的数据越多，缺失代价（miss penalty）越高（Lesson 9 会讲这个权衡）。

8.2 缓存设计四问与三种映射

  1. 怎么判断命中（hit）？比较标签（tag）：地址里的标签和缓存行（cache line）里存的标签相同（且有效位（valid bit）为 1）就是命中。

8.3 全相联 + LRU：最灵活的放法

老师上课提醒
  • 手算轨迹每一步：先算块（地址 ÷ 块大小（block size）取整，写出这一块的起止地址），再看 Index 选组，组内比 Tag。
  • 命中（hit）：什么都不换，只把这一行的 TSLR 清零、其他行加一。缺失（miss）：有空行先填空行，没空行踢 TSLR 最大（最久没用）的。
  • 考试里的手算轨迹题会短很多（大约 4 次访问），不会像课堂练习那样 9–12 次。

全相联（fully associative）：任何内存块都可以放进任何一行。地址只分两段：

Tag · 4 位（第 5–2 位）Offset · 2 位

偏移位数 = log₂(块大小) = log₂4 = 2；标签（tag）位数 = 地址位数 − 偏移位数 = 6 − 2 = 4（也等于 log₂(主存（main memory）块数) = log₂16）。每行除了数据，还要存标签和替换用的 LRU 信息。讲义用 TSLR（time since last referenced，距上次访问的次数）记录 LRU：每访问一次，所有有效行的 TSLR 加 1，被访问的行清零；要替换时踢 TSLR 最大的那行。

判断 HIT 还是 MISS：每一步问三个问题

判断命中只看一件事：这个地址所在的"块"，此刻是不是在缓存（cache）里。和这个地址本身以前有没有被访问过无关。

  1. 它属于哪个块？块大小 4 字节，块从 4 的倍数开始：块起点 = 地址 ÷ 4 取整再 × 4。例如 24 → 24–27，20 → 20–23，04 → 4–7，45 → 44–47。
  2. 这个块现在在缓存里吗？全相联时，4 行里任何一行有它都算。
  3. 在 → HIT，记下它刚被用过。不在 → MISS，把整块搬进来：有空行放空行；4 行都满了，踢掉最久没被用过的那一块（LRU）。

最容易想错的两点
  • 以前访问过 ≠ 一定命中（hit）。第 8 步的 24 第 1 步就访问过，但第 6 步被踢出去了，所以还是 MISS。
  • 没访问过 ≠ 一定缺失（miss）。命中按"块"算。Exercise 8.1 先访问 08，块 8–11 整块进了缓存（cache）；之后访问 09，虽然 09 是第一次出现，但它也在 8–11 里，所以是 HIT。这就是空间局部性（spatial locality）。

"在不在缓存里"到底怎么看

手算时，看你自己记下的缓存内容。缓存里有什么完全由前面的步骤决定，所以手算时每一步都要把当前缓存里的块记下来（上表最右一栏）。判断第 n 步时，只看第 n − 1 步那一行：要找的块在里面就是 HIT。例如第 8 步访问 24（块 24–27），第 7 步后缓存里是 44–47、20–23、4–7、12–15，没有 24–27，所以 MISS。

  1. 把地址拆开：本例地址 6 位，最低 2 位是偏移；全相联（fully associative）没有索引，高 4 位全是标签，标签其实就是块号（block number）。
  2. 拿地址的标签和缓存里存的标签逐个比较。
  3. 某一行标签相同且有效位为 1 → HIT；一个都不同 → MISS。空行有效位是 0，永远不会命中。

8.4 直接映射：每个块只有一个家

老师上课提醒
  • 老师喜欢的算法：块号（block number） B = ⌊地址 ÷ 块大小（block size）⌋，Index = B mod 组数（number of sets），Tag = ⌊B ÷ 组数⌋；或者直接把地址写成二进制切开。
  • 直接映射（direct mapped）：硬件简单但不灵活；全相联（fully associative）冲突最少但比较器（comparator）多；组相联（set associative）是折中（概念题素材）。

全相联每次都要比较所有行，大缓存（cache）里还要维护 LRU，硬件代价高。直接映射（direct-mapped）让每个内存块只能放在固定的一行：用地址中间几位做索引（index）直接选行。

偏移位 = log₂(块大小) = 2 索引位 = log₂(缓存行（cache line）数) = log₂4 = 2 标签（tag）位 = 地址位 − 索引位 − 偏移位 = 6 − 2 − 2 = 2 行号（line index） = 块号 mod 行数　（块号 = 地址 ÷ 块大小，取整）

查找三步：用 index 选中一行 → 比较这一行存的 tag 和地址的 tag → 相同则命中（hit），从行里按 offset 取字节；不同则缺失（miss），从主存（main memory）取块覆盖这一行。

同一个序列在直接映射下：24（行 10）、20（行 01）、04（行 01，踢掉 20）、12（行 11）、20（行 01，踢掉 04）、44（行 11，踢掉 12）、04（行 01，踢掉 20）、24 命中、44 命中，只有 2 次命中。20 和 04 都映射（mapping）到行 01，互相把对方踢出去，这就是冲突缺失（conflict miss）。

直接映射（direct mapped）不需要替换策略（replacement policy）

每个块只有一个位置可去，发生冲突时那一行原来的块直接被替换，不用 LRU、FIFO。这也是它比全相联（fully associative）便宜、快的原因之一。

讲义第 43 页的两个小问题

第 3 步表格里 24 那一行的标签（tag）写成了 00，应为 01（24 = 01 10 00₂）。另外第 3 步把 04 的缺失（miss）标成 conflict，但 04 是第一次被访问，同一页第 6 步的 44 情况完全相同却标成 compulsory。按定义两者都是 compulsory。

8.5 组相联：两者的折中

老师上课提醒
  • 组数（number of sets） = 行数 ÷ 路数（number of ways）。直接映射（direct mapped）：组数 = 行数；全相联（fully associative）：只有 1 组，Index = 0 位。

k 路组相联（k-way set-associative）把缓存行（cache line）分成若干组，每组 k 行。索引选中一组，块可以放在组内任意一行，组内满了按 LRU 替换。

组数 = 行数 ÷ k　　索引位 = log₂(组数) 组号（set index） = 块号（block number） mod 组数 k = 1 → 直接映射；k = 行数 → 全相联

讲义例题：4 行的 2 路组相联

把 4 行缓存（cache）两两分成一组：组 0 两行、组 1 两行。规则只有两条：每个块只能进一个固定的组（像直接映射）；进组之后组里两行随便放，组满了踢组里最久没用的那块（像全相联）。所以说它是两者的折中。

为什么这么惨：组 0 一直空着一行

组 0 从头到尾只用了一行，另一行一直空着；组 1 那边四个块抢两个座位，不停互相踢。它们不能去组 0 坐，因为组号（set index）由地址决定，没得选。这正是冲突缺失（conflict miss）：缓存（cache）其实还有空位，只是映射（mapping）规则不让用（8.6 节详细讲）。同一序列下全相联（fully associative）命中（hit） 3 次（第 7 步的 04 还在缓存里），2 路和直接映射（direct mapped）都只有 2 次。这个序列恰好不利于 2 路；一般情况下提高相联度能减少冲突缺失。

硬件上怎么判断命中：用 Index 位选出一组（例如 20 的 Index = 1，选组 1）；把地址的 Tag 和组内两行存的 Tag 同时比较，需要 2 个比较器（comparator）（直接映射 1 个，全相联 4 个）；有一行相同且有效位（valid bit）为 1 就命中。缺失（miss）时每组用 1 个 LRU 位记住哪一路最近用过，决定踢谁。

要分清两件事：每组最多同时装几块是硬件定死的；主存（main memory）里哪些块会被分到这一组由地址决定。

  • 每组最多同时装 k 块，固定不变。k 路组相联（set associative）每组有 k 行。本例 4 行 2 路：组数（number of sets） = 4 ÷ 2 = 2，组 0、组 1 各 2 行，各自最多同时装 2 块。组与组之间不能互相借位。
  • 主存的块平均分给各组，而且交替排列。组号 = 块号（block number） mod 组数。主存 64 字节共 16 块，偶数块归组 0，奇数块归组 1，每组"负责" 8 个块，但同一时刻只有 2 个座位。
  • 某次运行里各组实际装了几块，看访问序列。本例 1 块去组 0、4 块去组 1，所以组 1 挤得不停踢；如果顺序访问 0, 4, 8, 12, 16…，块号奇偶交替，两组会用得差不多平均。

冲突缺失到底是什么意思

缓存其实装得下，但映射（mapping）规则规定这个块只能去某一行（或某一组），偏偏那里被别的块占了，只好把它踢出去；后来再访问被踢掉的块，就缺失了。一句话：不是缓存太小，是座位分配规则太死。

打个比方

停车场 4 个车位，规定单号车只能停 A 区（2 个位），双号车只能停 B 区（2 个位）。连续来了 4 辆单号车：A 区两个位被反复争夺，后来的把先停的赶走；B 区一直空着一个位，但单号车不准停过去。被赶走的车再回来又找不到位，这就是冲突。如果改成"随便停"（全相联（fully associative）），4 辆车都停得下，就不会互相赶。

8.5 节的 2 路组相联（set associative）例子里，第 5、7 步就是冲突缺失（conflict miss）：第 4 步 12 进组 1 时把 20–23 踢掉，第 5 步再访问 20 就 MISS；第 5 步又把 4–7 踢掉，第 7 步访问 04 也 MISS。这两次缺失（miss）时组 0 都还空着一行，总容量是够的。

判断方法，按顺序问两步：

  1. 这个块是第一次被访问吗？是 → 强制缺失（compulsory miss），不管它有没有引起替换。
  2. 不是第一次的话，换成同样行数的全相联缓存（cache）（也用 LRU）跑同一个序列，这一步会命中（hit）吗？会命中 → 冲突缺失（全相联装得下，是映射（mapping）规则害的）；也缺失 → 容量缺失（capacity miss）（缓存本身太小，怎么放都装不下）。

验证：全相联在第 4 步后装着 24–27、20–23、4–7、12–15，第 5 步访问 20 会命中，所以 2 路这里的缺失是冲突缺失。反过来，全相联自己第 8 步访问 24 缺失，它没有映射限制，只能怪 4 行装不下，所以是容量缺失。标准 3C 模型里每次缺失只归入一类。冲突缺失只出现在直接映射（direct mapped）和组相联里，全相联没有冲突缺失；这也是提高相联度能降低缺失率（miss rate）的原因。

设计权衡
  • 直接映射（direct mapped）：硬件简单、面积小、访问快（索引直接定位，数据可以和标签（tag）比较并行读出）；但冲突缺失（conflict miss）多。
  • 全相联（fully associative）：没有冲突缺失，命中率（hit rate）通常最高；但比较器（comparator）多、功耗大、面积大，访问时间可能更长。
  • 同样的芯片面积：全相联可能命中率更高，直接映射可以做得更大。组相联（set associative）是两者的折中。

自测 · Self-Check

主存 256 字节、块 4 字节、缓存 8 行。全相联、直接映射、2 路组相联的地址分别怎么划分？
地址 log₂256 = 8 位，偏移 2 位。全相联（fully associative）：Tag 6 | Offset 2。直接映射（direct mapped）：8 行 → 索引 3 位，Tag 3 | Index 3 | Offset 2。2 路：4 组 → 索引 2 位，Tag 4 | Index 2 | Offset 2。这正是 Tutorial 8.8(i)。
直接映射里，地址 37 应该放进哪一行？标签是多少？（主存 256 B、块 4 B、8 行）
块号（block number） = 37 ÷ 4 = 9（取整），行号（line index） = 9 mod 8 = 1，标签 = 9 ÷ 8 = 1。用二进制看：37 = 001 001 01₂，Tag 001、Index 001、Offset 01，一致。
为什么直接映射不需要 LRU？
每个内存块只能放在唯一的一行，缺失（miss）时没有"选哪一行"的问题，原来那一行的块直接被替换。只有当一个块有多个候选位置（组相联（set associative）、全相联（fully associative））时才需要替换策略（replacement policy）。
A、B 两个块在直接映射缓存里反复互踢。这是什么缺失？换成全相联还会发生吗？
冲突缺失（conflict miss）。缓存（cache）里其实还有空行，只是映射（mapping）规则把 A、B 都指向同一行。换成全相联（fully associative）（或提高相联度）后两者可以同时待在缓存里，这类缺失（miss）就消失了。容量缺失（capacity miss）则不同，换成全相联也没用，只能加大缓存。
6 位标签、16 行缓存。直接映射和全相联各需要多少个比较器、多少次位比较？
直接映射（direct mapped）：1 个比较器（comparator），6 次位比较。全相联（fully associative）：16 个比较器，16 × 6 = 96 次位比较（Tutorial 8.7）。

本课课堂练习 · Exercises9.1

9.1 减少缺失：容量与相联度

  • 强制缺失（compulsory miss）：第一次访问，躲不掉；程序跑几百万条指令时，这部分可以忽略。
  • 冲突缺失（conflict miss）：办法 1 是加大缓存（cache）（每行被更少的地址共享），办法 2 是提高相联度（每组多几行）。
  • 容量缺失（capacity miss）：缓存装不下程序用到的所有块（例如缓存 64 KB、程序 64 MB），只能加大缓存。

讲义的统计图给了两条经验：缺失率（miss rate）随缓存变大和相联度变高而下降；4 路组相联（set associative）的缺失率约等于两倍大的直接映射（direct mapped）缓存。从直接映射到 2 路收益最大，在很多情况下缺失率能降 20% 以上；再往 4 路、8 路走，收益越来越小，而硬件复杂度和访问时间却在增加。

9.2 块大小的权衡

老师上课提醒
  • 块太大：缺失率（miss rate）先降后升（块数变少，冲突 / 容量缺失（capacity miss）增加），缺失代价（miss penalty）变大；常用 64–128 字节。
  • 加大容量比加相联度效果更明显；相联度高了以后再加，收益很小。
大块的好处大块的坏处
更好地利用空间局部性（spatial locality），减少强制缺失（compulsory miss）缓存（cache）容量固定时块数变少，冲突/容量缺失增加（还会削弱时间局部性（temporal locality））
同样容量下需要的标签（tag）更少每次缺失（miss）要传更多字节，缺失代价变大
块太大时，取回来的很多字节根本用不上，浪费空间和带宽
缺失代价 = 取到第一个字节的延迟（latency） + 其余字节的传输时间 经验规则：块大小（block size） < √(缓存大小)；常见选择 64–128 字节 目标：选让 AMAT = HT + MR × MP 最小的块大小

讲义演示：2 组、8 字节块的直接映射（direct mapped）缓存，访问 24 时整个 24–31 块进入缓存，随后访问 28 直接命中（hit），尽管 28 从没被访问过。这就是块大小带来的空间局部性收益。Tutorial 9.6 用一个只有一块的缓存把这个效果量化：块 8 B 时缺失率 50%，16 B 时 37.5%，32 B 时 25%。

9.3 地址位划分通用方法

老师上课提醒
  • 地址位 = log₂(主存（main memory）字节数)；Offset = log₂(块字节数)；Index = log₂(组数（number of sets）)；Tag = 其余。
  • 注意 K / M / G：1 KB = 2¹⁰ = 1024 字节，不是 1000；"256 KB" 和 "256 B" 差了 10 位。块大小（block size）给的是"字"时先乘 4 换成字节。
  • 还会考"反推"：给 Tag 位数和块数，倒推块大小和容量；Index 算出来是 0 就说明是全相联（fully associative）。

缓存（cache）由三个参数决定：组数、相联度（每组块数）、块大小。

缓存容量 = 组数 × 相联度 × 块大小 块数（行数）= 容量 ÷ 块大小 组数 = 块数 ÷ 相联度 Offset = log₂(块大小)　Index = log₂(组数)　Tag = 地址位 − Index − Offset

块数怎么算：容量 ÷ 块大小

块数就是缓存一共能放多少个块，也就是缓存有多少行。关键是先把两个数换成同一单位（字节），再写成 2 的幂。以 Exercise 9.1（32 KB 缓存、256 B 块）为例：

  1. 把 32 KB 换成字节：1 KB = 1024 = 2¹⁰，32 = 2⁵，所以 32 KB = 2⁵ × 2¹⁰ = 2¹⁵ = 32768 字节。
  2. 块大小写成 2 的幂：256 = 2⁸。
  3. 2 的幂相除就是指数相减：2¹⁵ ÷ 2⁸ = 2⁷ = 128 块。直观地说，32768 字节的数据区切成每份 256 字节，正好 128 份，每份一行、放一个块。

后面几步都从这个 128 出发：Offset = log₂256 = 8（一块 256 字节，编号 0–255 要 8 位）；组数 = 128 ÷ 相联度（直接映射（direct mapped） 128、4 路 32、全相联 1）；Index = 7、5、0；Tag = 32 − Index − 8 = 17、19、24。

9.4 写策略：主存怎么拿到正确的值

老师上课提醒
  • 写直达（write-through）和写回（write-back）的区别要记住（老师原话 "remember the differences"）。现代缓存（cache）多用写回，因为性能更好。
  • 写分配（write allocate）（先把块搬进缓存再写，常配写回）vs 不写分配（no-write allocate）（直接写主存（main memory），常配写直达）。写缓冲（write buffer）让 CPU 不用等写完。
  • 多核缓存一致性（MESI）超出本课范围，只提了一下。

四种情况总表、"读缺失（read miss）也会写主存"、完整的读写序列例子和判断题自测，见 缓存专题 B 部分。

写和读不一样：写不一定要让 CPU 等（可以用写缓冲），但写会修改缓存，于是缓存和主存可能暂时存着同一数据的不同版本；有些 I/O 设备（DMA）还会绕过缓存直接读主存。四种机制：

写缓冲把要写主存的数据先放进缓冲区，CPU 继续执行常和写直达搭配；缓冲满了 CPU 仍要等

为什么"写"会带来麻烦

读只是把数据复制一份到缓存，缓存和主存内容一样，不会出问题。写会改值：缓存里有块 100–103 = A B C D，主存也是 A B C D；CPU 把 X 写到 101，缓存那份变成 A X C D，主存那份改不改？不改的话，同一个地址在两处就是两个不同的值。主存的值在这几种时候要紧：

  • 块被踢出缓存时：缓存里的新值若没写回主存，就永远丢了。
  • I/O 设备（DMA）直接读主存时：它绕过缓存，会读到旧值。
  • 多核时：别的核读到的也可能是旧值。

写策略（write policy）要解决的就是"什么时候、怎么把新值交给主存"。

写命中：写直达 vs 写回，逐步对比

"写命中（write hit）"指要写的块已经在缓存里。依次执行 Store X → 101、Store Y → 102、Store Z → 101，最后这个块被替换出缓存（Tutorial 9.4）：

  • 写直达（write-through）：每次写，缓存和主存同时更新。好处是主存永远最新、简单可靠，块被踢时直接丢掉；坏处是每次写都要访问慢速的主存，流量大。上例写了 3 次主存，第一次写的 X 后来还被 Z 覆盖，等于白写。
  • 写回（write-back）：写的时候只改缓存，等这个块被踢出缓存时才一次性写回主存。好处是同一块的多次写合并成一次，流量小、速度快（上例 X 根本没写到主存）；坏处是主存有一段时间是旧的，控制更复杂，踢块时若要先写回会多花时间。

脏位（dirty bit）是什么

脏位是缓存每一行上额外的 1 个比特，标记"这一行被改过没有"。"脏"的意思是这份副本已经被改动，和主存里的原件不一样了。

脏位意思这一行被踢出时
0（clean）缓存里这份和主存那份一模一样直接丢掉，什么都不用做
1（dirty）这一行在缓存里被写过，主存那份已经是旧的必须先把整块写回主存，再丢掉
每一行存：| 有效位（valid bit） V | 脏位 D | 标签 Tag | 数据（整个块） |
  • 每一行（每个块）1 位，不是每个字节 1 位。块里哪怕只改了一个字节，整行就算脏，写回时整块一起写。
  • 什么时候变：块从主存搬进缓存时 D = 0；对这一行写（store）时 D = 1；只读不改变 D；被踢出时看 D 决定要不要写回。
  • 只有写回策略才需要脏位：写回在写时不改主存，必须记住哪些行的主存副本已经过期。只读过的块 D 一直是 0，踢出时不用白写一次主存，这也是写回省流量的地方。写直达每次都同时改主存，行永远是"干净"的，不需要脏位。
  • T9.4(c) 问每次操作后的脏位：初始 0，三次写之后都是 1、1、1，直到块被写回、踢出。

写缓冲：让写直达不那么慢

写和读不一样：读时 CPU 必须拿到数据才能继续算；写时 CPU 不需要拿回任何东西。所以可以加一个小队列：CPU 把"地址 + 数据"往缓冲里一放就继续执行，缓冲在后台慢慢写进主存，好比把信投进邮筒就走，不用等邮递员送到。只有缓冲满了（写得太快，主存来不及消化），CPU 才要停下来等。写缓冲通常和写直达搭配。

缓存一致性是多核的问题：每个核有自己的缓存，核 1 改了 x，核 2 缓存里还是旧的 x，需要 MESI（Modified / Exclusive / Shared / Invalid）这类协议来通知和作废旧副本。讲义说超出本课程范围，知道名字即可。

9.6 多级缓存 公式不考

第 9 周老师讲完两级缓存（cache）的例子后说，多级缓存（multilevel cache）的公式只是给大家参考，保证 quiz 和 final 都不考。只要知道"L1 缺失（miss）时先去 L2，比直接去主存（main memory）代价小得多，所以加 L2 能降低停顿（stall）"就够了。下面的内容可以快速浏览。

只有一级缓存时，L1 缺失就得直接去主存，一次要等 100 个周期；L1 又不能做大，做大了就变慢。办法是在 L1 和主存之间再加一层更大一点、稍慢一点的 L2（芯片面积够时还有 L3）：

CPU → L1（很小、很快）→ L2（大一些、慢一些）→ 主存（很大、很慢）
  • L1 缺失先找 L2：L2 有，只付 L2 的时间（比如 19 或 25 周期），不用去主存；L2 也没有，才去主存。
  • L2 通常是统一缓存：指令和数据共用一个 L2；L1 则分成指令缓存和数据缓存两个。

9.7 虚拟内存与 TLB 不考

第 9 周老师说时间不够，虚拟内存只录一个视频放到 NTULearn，quiz 和 final 都不考，mock quiz 里的虚拟内存题也会删掉。这一节和地址翻译动画留着，有兴趣再看；复习时间紧可以直接跳到 Lesson 10。

先抓住一句话：程序用的地址是"假的"（虚拟地址（virtual address）），每次访存（memory access）前都要翻译成"真的"（物理地址（physical address））。TLB 是为了让这个翻译变快而加的小缓存（cache）。

为什么需要虚拟内存

电脑里同时跑着几十个程序，共用一块物理内存。如果每个程序直接用物理地址：程序得知道自己被放在内存哪里，两个程序都想用地址 1000 就打架；程序比内存大就没法运行；一个程序写错地址，可能改坏别的程序甚至操作系统。

虚拟内存是一层间接映射（mapping）：每个程序都以为自己独占一整片从 0 开始的地址空间（32 位就是 4 GB），程序里写的都是虚拟地址，由硬件和操作系统偷偷翻译成物理地址。讲义列的三个问题就这样解决了：

问题怎么解决
程序比物理内存大暂时不用的部分放在磁盘上，用到时再调进内存，造成"内存无限大"的假象。主存（main memory）相当于磁盘的缓存，靠的仍是局部性（locality）
空闲内存碎片化每个程序各有一套翻译表，程序的各块可以分散放在主存的不同位置，零散的空闲内存也能用上
安全与共享程序只能访问自己翻译表里有的地址，看不到别人的私有数据；需要共享时让两张表指向同一块物理内存

页缺失（page fault）

访问 0x22222000 时，VPN = 0x22222，页表有效位是 0，这一页不在内存里，就是页缺失：

  1. 硬件发现有效位为 0，触发异常（精确中断），交给操作系统。
  2. 操作系统从磁盘把这一页读进某个空闲物理页（内存满了就先换出一页）。
  3. 填好页表：写上 PPN，有效位置 1。
  4. 回到那条指令重新执行，这次就能翻译成功。

磁盘太慢，一次页缺失要几毫秒，也就是几百万个周期。有效位的作用：标记"这一项的翻译能不能用"，防止用到无效的 PPN。

TLB：翻译结果的"缓存"

问题：页表在主存里，CPU 每次读写内存都得先去主存读一次页表项才知道物理地址，访存次数直接翻倍。解决办法是 TLB（Translation Lookaside Buffer，快表）：CPU 里一个很小、很快的缓存，专门存最近用过的几条翻译（VPN → PPN）。一般不超过 128–256 项，比数据缓存还快；和普通缓存一样可以是全相联、组相联或直接映射。每项含有效位、VPN（当作标签）、PPN、脏位、引用位、访问权限。

自测 · Self-Check

32 位地址、64 KB 缓存、64 B 块。直接映射、4 路、全相联的 Tag / Index / Offset 各几位？
块数 1024，Offset 6。直接映射（direct mapped）：1024 组，Index 10，Tag 16。4 路：256 组，Index 8，Tag 18。全相联（fully associative）：1 组，Index 0，Tag 26。（Tutorial 9.5）
为什么固定容量下块不能无限加大？
容量固定时块越大块数越少，能同时留在缓存（cache）里的不同区域越少，冲突和容量缺失（capacity miss）增加；而且每次缺失（miss）要传的字节更多，缺失代价（miss penalty）上升，很多取回来的字节可能用不到。所以缺失率（miss rate）随块大小（block size）先降后升，AMAT 也有最低点，常见最佳值 64–128 B。
写回缓存里，对同一块连写 3 次，主存一共被写几次？写直达呢？
写回（write-back）：只在块被替换时写回 1 次（脏位（dirty bit）为 1）。写直达（write-through）：每次写都更新主存（main memory），3 次。
L1 局部缺失率 5%，L2 局部缺失率 2%。L2 的全局缺失率是多少？代表什么？
5% × 2% = 0.1%。意思是 CPU 发出的所有访问中，有 0.1% 在 L1 和 L2 都缺失（miss），最终要去主存（main memory）。
TLB 缺失一定意味着页缺失吗？
不一定。TLB 只缓存（cache）最近的翻译。如果页在内存里只是 TLB 没记，就从页表（page table）把翻译装进 TLB（几十个周期）；只有页表项有效位（valid bit）为 0、页根本不在内存时才是页缺失（page fault）（百万周期级，由操作系统处理）。

10.1 延迟、吞吐与关键路径

  • 延迟（latency）：一个工作单位从进入系统到完成所需的时间。
  • 吞吐量（throughput）：单位时间内系统能完成的工作单位数。
  • 并行的目标：提高吞吐量；有时也能降低延迟。

组合电路的延迟由关键路径（critical path）决定：从输入到输出所有路径中门延迟之和最大的那条。讲义的 1 位全加器：AND、OR、非门各 tg，XOR 为 3tg，关键路径 A → XOR → XOR → S，延迟 6tg，吞吐量 = 每 6tg 完成一次加法 = 1/(6tg)。

找关键路径（critical path）的方法

从输入开始，给每个门的输出标上"最早稳定时间" = 它所有输入的最晚稳定时间 + 本门延迟（latency）（输入端的小圆圈是非门，要单独加一个非门延迟）。输出端的时间就是延迟，倒推取最大值的那条输入就是关键路径。Exercise 10.1、10.2 的完整解答见习题小程序。

10.2 空间并行 vs 时间并行

  • 空间并行：多套硬件同时工作，同时处理多个任务。通常直接叫"并行"。
  • 时间并行：把任务切成几级（像流水线（pipeline）工厂），不同任务同时处在不同级，执行在时间上重叠。这就是流水线。

10.3 流水线总时间公式

洗衣房例子：4 个人各有一筐衣服，洗 30 分钟、烘 40 分钟、叠 20 分钟。顺序做要 4 × 90 = 360 分钟（6 小时）。流水起来，一台机器空出来就接下一筐：

Ttotal = Tfirst + (n − 1) × Tcycle Tfirst = ΣTi（第一个任务走完所有级）　Tcycle = max Ti（最慢的一级） 洗衣房：30 + 40 + 20 + (4 − 1) × 40 = 210 分钟

如果每级时间相同、各占 1 个周期，k 级流水线（pipeline）处理 n 个任务需要 k + n − 1 个周期（Tutorial 10.1：第一个任务 k 个周期出来，之后每周期出一个）。

流水线的几条结论

  • 流水线不降低单个任务的延迟（latency），提高的是整批工作的吞吐量（throughput）。
  • 吞吐量受最慢的一级限制。
  • 理论最大加速比（speedup）约等于级数；各级时间不均衡会降低加速比。
  • 填充（filling）和排空（draining）流水线的时间也会拉低加速比，任务越多这部分影响越小。
两种算法，看题目设定

讲义里出现了两种模型。任务流水（洗衣房、Tutorial 10.5/10.6 写明"一级做完就能立刻接下一个任务"）：第一个任务只需 ΣTi，用上面的公式。时钟流水（处理器、DLX）：每级都被拉长到一个时钟周期（clock cycle），第一条指令的延迟（latency） = 级数 × 时钟周期（讲义 5 × 250 = 1250 ps），总时间 = (k + n − 1) × Tclk。n 很大时两者几乎相等，加速比（speedup）都趋近 ΣTi / max Ti。

10.5 DLX 寄存器、数据类型与指令

老师上课提醒

DLX（读作 "deluxe"）是教学用的简化 RISC 处理器，结构和 MIPS 很像，五级流水线（pipeline）：取指（instruction fetch）、译码（instruction decode）、执行、访存（memory access）、写回（write-back）。和 MIPS 相比，DLX 指令更少、寻址模式（addressing mode）更简单，冒险（hazard）处理也用教学化的例子。

  • 32 个 32 位通用寄存器（register） R0–R31。R0 恒为 0（只读，写它无效）；R31 是链接寄存器，JAL/JALR 把返回地址存在这里。

  • 立即数（immediate）是 16 位，嵌在 I 型指令里（ADDI、LW 等）。

11.6 流水线性能与要点

理想情况下五级流水线（pipeline）每个周期完成一条指令，CPI = 1。讲义例子：非流水 DLX 时钟 1 ns，ALU 指令 4 周期（40%）、分支（branch） 4 周期（20%）、访存（memory access）指令 5 周期（40%）；流水化额外增加 0.1 ns 时钟开销（寄存器（register）延迟（latency）、时钟偏移）。

非流水 CPI = 0.4 × 4 + 0.2 × 4 + 0.4 × 5 = 4.4　→　每条 4.4 × 1 ns = 4.4 ns 流水：CPI ≈ 1，时钟 1.0 + 0.1 = 1.1 ns　→　每条 1.1 ns 加速比（speedup） = 4.4 / 1.1 = 4 通式：平均每条指令时间 = CPI × 时钟周期（clock cycle）；加速比 = 非流水时间 / 流水时间
  • 流水线提高的是吞吐量（throughput），不减少单条指令的延迟。
  • 单端口存储器里，取指（IF）和访存（MEM）要同时用存储器，不同指令会抢同一资源，这就是结构冒险（structural hazard），需要停顿（stall）。
  • 实际流水线因为冒险（hazard），CPI > 1。三类冒险是 Lesson 12 的内容。

ADD R7, R3, R4，R3 = 25，R4 = 17，PC = 200。每一级的关键输出是什么？

为什么 ID 阶段对 R 型指令也做符号扩展？会出错吗？
ID 阶段的译码（instruction decode）、读寄存器（register）和符号扩展（sign extension）是并行做的（固定字段译码），硬件不必等译码完成再决定做不做扩展，这样更快。R 型指令只是不用 Imm（EX 的 MUX 选 B），所以不会出错。
LW 和 ADD 在 EX 阶段，ALU 第二个输入的 MUX 分别选什么？
LW 选 Imm（算 A + Imm 得有效地址）；ADD 选 B（算 A + B）。分支（branch）指令第一个输入选 NPC，第二个选 Imm（算目标地址）。
非流水实现里 CPI = 4.6、时钟 0.8 ns；流水线 CPI = 1.2、时钟 1.0 ns。加速比多少？
非流水 4.6 × 0.8 = 3.68 ns，流水 1.2 × 1.0 = 1.2 ns，加速比（speedup） 3.68 / 1.2 ≈ 3.07（Tutorial 11.8）。
为什么 b（目的寄存器号）要一路存到 M/W，而不是在 ID 直接写好？
寄存器（register）要到 WB 阶段才写，而这时 ID 里已经是后面第三条指令了，它的 IR 字段已经换成别的值。所以目的寄存器号必须跟着自己的指令在 D/A → A/M → M/W 里一级级往下传，WB 时才知道写哪个寄存器。

LESSON 12

流水线冒险

Final 范围

理想流水线（pipeline） CPI = 1，加速比（speedup）等于级数。现实里，下一条指令经常不能在它该进入的那个周期进入：要么硬件资源被占（结构冒险（structural hazard）），要么要用的数据还没算出来（数据冒险（data hazard）），要么连下一条该取哪条都还不知道（控制冒险（control hazard））。这一课逐个分析三类冒险（hazard），以及转发（forwarding）、互锁、编译器调度（compiler scheduling）、分支预测（branch prediction）、延迟（latency）槽这些对策，最后都落到一个公式上：CPI = 1 + 每条指令的平均停顿（stall）周期。

12.2 结构冒险

两条或更多指令在同一周期要用同一个硬件资源，资源又不能同时满足，就是结构冒险（structural hazard）。例子：寄存器（register）堆只有一个写端口；指令和数据共用一个单端口存储器。解决方法：停顿（stall）到资源空出来，或者复制资源（双端口存储器有两套独立的地址、数据和控制信号，一个端口给 IF，一个给 MEM，冲突就消失了）。

讲义例子：LOAD 在第 4 周期处于 MEM，此时第 4 条指令正要 IF，两者都要访问存储器，只能让取指（instruction fetch）晚一拍。

40% 的指令是 load/store，每条造成 1 周期结构停顿 CPI = 1 + 0.4 × 1 = 1.4 即使时钟快 5%：平均指令时间 = 1.4 × Tideal / 1.05 = 1.33 Tideal

结论：消除结构冒险往往比小幅提高主频更划算。

12.4 寄存器分半周期与转发

序列 ADD R1,R2,R3 后面跟着 SUB R4,R1,R5、AND R6,R1,R7、OR R8,R1,R9、XOR R10,R1,R11。ADD 在第 5 周期（WB）才写 R1：

  • 寄存器（register）堆分半周期：一个周期内前半写、后半读。所以和 WB 同一周期的 ID 能读到新值。
  • SUB 在第 3 周期读 R1、AND 在第 4 周期读 → 都读到旧值，有冒险（hazard）。
  • OR 在第 5 周期的后半读，正好拿到 ADD 前半写进去的新值 → 无冒险。XOR 更晚，也没问题。
  • 结论：没有转发（forwarding）时，只有紧跟其后的两条指令需要停顿（stall）。

转发（forwarding，也叫旁路 bypassing）：结果其实在 EX 结束时就已经算出来了，没必要等写回（write-back）寄存器堆。把 EX/MEM（A/M）和 MEM/WB（M/W）流水线寄存器（pipeline register）里的值直接送回 ALU 输入端：

  • 硬件：在 ALU 每个输入前加一个 MUX，加上从 EX/MEM、MEM/WB 回来的通路，再加冒险检测逻辑来选输入。
  • 正常情况选寄存器堆读出的值；检测到冒险就选转发来的值。
  • ADD → SUB、SUB → AND 这类 ALU 到 ALU 的 RAW 全部可以零停顿解决。紧挨着的那条从 EX/MEM 拿值（Exercise 12.10 选 B）。

12.6 编译器调度消除停顿

与其让硬件停顿（stall），不如让编译器把不相关的指令挪进停顿的位置，让 CPU 在等数据的那一拍干点有用的活。只要被移动的指令和周围没有依赖，程序结果就不变。

a = b + c; d = e − f;（变量都在内存里，有转发（forwarding））
原始代码调度后
LW Rb,b
LW Rc,c
ADD Ra,Rb,Rc　← 停 1 拍
SW a,Ra
LW Re,e
LW Rf,f
SUB Rd,Re,Rf　← 停 1 拍
SW d,Rd		 LW Rb,b
LW Rc,c
LW Re,e　← 提前，填掉空拍
ADD Ra,Rb,Rc
LW Rf,f
SW a,Ra
SUB Rd,Re,Rf
SW d,Rd

调度后 ADD 距离 LW Rc 隔了一条，SUB 距离 LW Rf 也隔了一条，两次 load-use 停顿都消失了，不需要额外硬件。

    12.7 控制冒险

    原始 DLX 在 EX 级才算出分支（branch）目标和判断条件。等结果出来时，后面已经有三条顺序指令进了流水线（pipeline）；如果分支跳转，这些指令都不该执行。最简单的办法是停顿（stall）：

    原始 DLX：分支代价（branch penalty） 3 周期　CPI = 1 + 0.3 × 3 = 1.9（分支占 30%） 改进 DLX：在 ID 级加一个比较器（comparator）判断条件、一个加法器算目标地址 　　　　　分支代价降为 1 周期　CPI = 1 + 0.3 × 1 = 1.3
    为什么是 3 不是 2

    严格说，EX 结束时结果就知道了，下一拍就能取目标，代价是 2。讲义按经典 DLX 的做法，在 MEM 级才把新 PC 写回（write-back），所以记为 3 周期。考试按讲义：EX 判定 = 3，ID 判定 = 1。题目给定了代价（如 Tutorial 12.8 的"错误预测代价 3"）就直接用给定值。

    实测统计：条件分支（branch）约占指令的 14–16%；向前分支约 60% 跳转，向后分支（循环）约 85% 跳转，整体约 67% 跳转。分支又多又常跳，所以值得做预测。

    填延迟槽的三种来源

    来源做法安全性适用
    From before把分支前面一条无关指令挪进槽里（分支条件不能依赖它）高，本来就要执行首选
    From target把跳转目标处的第一条指令复制进槽里中：不跳转时它也会执行常跳的分支，比如循环末尾的向后分支
    From fall-through把不跳转时会执行的下一条挪进槽里中：跳转时它也会执行常不跳的分支，比如 if 语句的向前分支

    Tutorial 12.3 是一个带修改的 from-before 例子：循环里把 SW 200(R3),R2 挪到 BNEZ 后面的槽里，但它前面的 SUBI R3,R3,#4 已经把 R3 减了 4，所以偏移要改成 SW 204(R3),R2 才能存到原来的地址。

    可取消分支（canceling / nullifying branch）：编译器同时给出预测方向，预测对了槽里的指令正常执行，预测错了就把它当 NOP 作废，不会产生错误结果。延迟槽的问题是合适的指令常常找不到、from target / fall-through 不一定安全、流水线（pipeline）一深就要填好几个槽，所以现代 CPU 改用硬件动态分支预测（branch prediction）：猜对零代价，猜错冲刷流水线重来。

    做法谁来解决性能硬件复杂度
    NOP 延迟槽没人差（每个分支浪费 1 拍）很低
    填充延迟槽编译器较好（常为 0 代价）低
    分支预测硬件最好高

    ADD R1,R2,R3 后面是 LW R2,0(R5)。这是什么冒险？会在 DLX 里出问题吗？
